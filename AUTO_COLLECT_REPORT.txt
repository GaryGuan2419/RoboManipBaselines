# Dingo-Z1 自动化采集脚本进展总结 (2026-02-25)

## 📍 当前状态
已完成针对 `auto_collect.py` 的深度诊断。通过 `debug_gripper.py` 成功识别出导致 0/50 失败的 4 个硬伤。

## 🚨 核心诊断发现（“雷坑”细节）
1. **坐标系偏移 (EEF Offset)**: 
   - 脚本目前追踪的是 `link06`，但在 MuJoCo 模型中，真正的夹爪尖端距离 `link06` 有约 **18.6cm** 的位移。
   - 后果：机械臂实际上是用“手腕”在对准物体，手指已经伸到了方块前方 18 厘米处。
2. **夹爪力矩/行程**: 
   - 之前使用的 `-0.8` 指令只完成了 53% 的行程。
   - 建议：改为 `-1.5` 以实现完全闭合，锁死 3cm 方块。
3. **朝向偏差**: 
   - 种子关节角 `[0, 1.0, -0.5, 0, -0.5, 0]` 产生的朝向与垂直向下偏离巨大（Dot=0.421）。
   - 建议：直接指定 `quat = [0.707, 0, 0.707, 0]` 等固定朝下四元数。
4. **控制效率**: 
   - 每步 1cm 的 IK 步进太慢。
   - 建议：放大至 2.5cm，配合 `damping=0.08` 维持稳定。

## 🛠️ 下一步捡起来怎么做？
如果你之后想重新启用自动化：
1. 打开 `implementation_plan.md`（在 .gemini/antigravity/brain 下）。
2. 将 `link06` 的坐标点在物体方向上“回退” 18.6cm，或者改用 `gripperMover` 作为 IK 目标体。
3. 设置 gripper 动作为 `-1.5`。
4. 强制指定 EEF 朝向向下，不依赖之前的 Arm Seed。

## 📝 决策说明
由于项目当前只需要 30-50 条演示数据，用户决定优先通过 **手动 Teleop** 完成 Phase 2。
手动采集卡顿的疑似原因：`robo_manip_baselines` 包未在 `gym` 环境中正确注册，导致 `make` 环境失败。
